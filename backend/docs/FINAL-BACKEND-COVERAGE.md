## Validation boundary

Tests use isolated PGlite with synthetic fixtures, Supabase-like auth/storage scaffolding and injected provider transports. This validates SQL workflow/privilege behavior and contract boundaries, not real Supabase infrastructure, external services, network security or multi-session PostgreSQL race behavior. The main test command includes every runnable suite. Read CONTINUE.md for the final verified count and build result. No test was removed; provenance expectations now isolate encounter revisions while checking additional authorized source categories.

## Deployment blockers

Review migration compatibility against a fresh live schema export before staging application;004 is the sole live reconciliation baseline. Run production-like Auth/Storage/Edge and concurrency tests, configure trusted adapter/webhook authentication and real provider credentials, verify dataset licensing/source accuracy, validate clinical governance/retention and conduct independent security/compliance review. Final-source ZIP is a reviewable handoff, not a production deployment approval.
